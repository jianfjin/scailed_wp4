📋 实施概要 / Summary

P5 灾难恢复手册。覆盖 5 种故障场景，从本地 Docker 崩溃到异地全毁。每场景含恢复步骤、预估时间、验证清单。目标 RPO ≤ 24h，RTO ≤ 1h。

System Profile

DatabasePostgreSQL 16 + Apache AGE 1.5.0 DB size~9.6 MB Backup size~72 KB / day Local backup/backups/pg/ — 7-day retention Cloud backupCloudflare R2 scailed-backups/pg/ — €0 Containers8 (traefik, frontend, backend, postgres, redis, wp2/3/8-mock) RPO target≤ 24 hours RTO target≤ 60 minutes
S1: PostgreSQL Corruption MOST LIKELY
Bad migration · DROP TABLE · filesystem error on pgdata

RTO: ~15 min   RPO: 0–24 h 

# 1. Stop app
docker compose stop backend frontend

# 2. Verify backup
bash deploy/verify_restore.sh

# 3. Wipe + recreate volume
docker compose stop postgres
docker volume rm scailed_pgdata
docker volume create scailed_pgdata
docker compose up -d postgres
sleep 10

# 4. Restore
DUMP=$(ls /backups/pg/latest/pathfinder_*.dump)
docker cp "$DUMP" scailed-postgres:/tmp/restore.dump
docker exec scailed-postgres pg_restore -U pathfinder -d pathfinder \
  --clean --if-exists /tmp/restore.dump

# 5. Verify + restart
bash deploy/verify_restore.sh
docker compose up -d backend frontend
curl -f http://localhost/health
S2: Host Disk Failure
Disk corruption · accidental rm -rf · OS reinstall

RTO: ~40 min   RPO: 0–24 h

# 1. Fresh OS + deps
sudo apt install -y docker.io git rclone

# 2. Clone + configure
git clone https://github.com/jianfjin/scailed_wp4.git ~/projects/scailed_wp4
bash ~/projects/scailed_wp4/deploy/setup-r2.sh

# 3. Pull from R2
mkdir -p /backups/pg
rclone sync r2:scailed-backups/pg/ /backups/pg/latest/

# 4. Build + start + restore
cd ~/projects/scailed_wp4/deploy
docker compose up -d --build
sleep 30
DUMP=$(ls /backups/pg/latest/pathfinder_*.dump)
docker cp "$DUMP" scailed-postgres:/tmp/restore.dump
docker exec scailed-postgres pg_restore -U pathfinder -d pathfinder \
  --clean --if-exists /tmp/restore.dump
bash deploy/verify_restore.sh

# 5. Re-establish cron (backup + verify)
S3: R2 Unavailable
R2 outage · token expiry

RTO: ~5 min   RPO: N/A (local safe)

# Local backups unaffected. Just switch remote:
rclone config create wasabi s3 provider=Wasabi ...
export SCAILED_RCLONE_REMOTE=wasabi
bash deploy/backup.sh  # syncs to Wasabi now
S4: Complete Site Loss WORST CASE
Fire · flood · theft · physical destruction

RTO: ~60 min   RPO: 0–24 h

# Same as S2. Only R2 survives.
# New machine → git clone → rclone pull → docker compose up → pg_restore → verify
# Also restore: Hermes agent config, SSH keys, VM bridge if applicable.
S5: Silent Data Corruption
Bit rot · buggy code · AGE inconsistency

RTO: ~30 min + re-apply   RPO: detection-dependent

# Weekly verify catches this. Find last clean backup:
for dir in /backups/pg/202*; do
  bash deploy/verify_restore.sh "$dir"
done
# Restore from last known-good, then re-apply legitimate changes.

🚨 EMERGENCY QUICK REFERENCE

1. DON'T PANIC.  Local + R2 = two independent copies.
2. Stop app:   docker compose stop backend frontend
3. Verify:     bash deploy/verify_restore.sh
4. Identify:   Which scenario? (S1–S5)
5. Execute:    Follow scenario procedure above.

Key paths:
  Local:    /backups/pg/
  Cloud:    r2:scailed-backups/pg/
  Deploy:   ~/projects/scailed_wp4/deploy/
  Docker:   ~/projects/scailed_wp4/deploy/docker-compose.yml

Restore one-liner:
  docker cp <dump> scailed-postgres:/tmp/r.dump &&
  docker exec scailed-postgres pg_restore -U pathfinder -d pathfinder
    --clean --if-exists /tmp/r.dump
