# 类型参考能力不自动成为本次评估能力

类型层能力信息可以帮助设计问卷或展示参考画像，但不能直接说明当前评估对象具备相应能力；用户在领域建模讨论第 6 问选择只将其作为类型参考。决定：WP2 分类中的类型能力不自动继承为本次评估的能力默认值，本次能力判断依据本次回答与相应证据形成。能力词汇与源内容的含义仍按 ADR 0004 由相应内容负责方确认，回答、自报、推导和核验的区别在评估语言中继续细化。

## 未知与明确否定

用户在第 7 问选择分别表达未知与明确不具备：未回答且没有其他依据时保持未知，不默认解释为已具备或明确不具备。

## 必要条件未知时的输出

用户在第 8 问选择允许 V1 提供条件性方向和待补信息，同时明确尚不能确认相关路径可执行。未知不自动成为已满足的条件或已确认受阻的事实；条件性方向与顶层结果状态之间的具体映射仍需结合交界约定确认。

## 自报与核验

用户在第 9 问选择允许以用户自报进行注明依据的推演，标明「自报具备、未核验」并保留来源，不自动升级为已核验事实。能力判断与核验状态分别表达；当前问卷的填写完整度或 confidence 不构成对自报真实性的核验。

## 实现与契约对照

旧有 WP2/WP3 自动推导路径会从 WP2 记录生成能力、缺口和成熟度，虽然标记推导来源，也不能因此把推导结果等同于本次回答或核验事实；后续实现评审需要核对其适用范围。已激活边界代次的推荐路径要求先提交问卷，当前讨论不构成所有运行模式均已符合该原则的声明。

现有条件求值返回布尔值，否定运算直接反转结果；比较与集合判断还需要与未知状态的领域语义对照。术语层已确认未知与否定不同，不代表规则语言及运行时已支持这一差别。

本 ADR 记录本仓库已接受的设计原则。涉及共享字段含义或交界约定的调整，仍需受影响生产方与消费方确认；核验责任、对应证据及结果状态的具体表达在[讨论记录](../domain-modeling/2026-11-26-cross-wp-ddd.md)中继续确定。
