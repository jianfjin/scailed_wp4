# 被撤回的输入版本停止用于生成新建议

内容方撤回已发布版本时，继续使用可以维持建议输出，但会把技术上仍可读取的输入误当作当前仍有效的依据；用户在领域建模讨论第 11 问选择停止基于该版本生成新建议。决定：内容负责方明确撤回当前使用的某个输入版本后，即使替代版本尚未通过验收，也停止以被撤回版本生成新的建议。历史评估保留原输入版本和结果，同时明确呈现来源已撤回，历史结果不再作为当前有效建议。

## 与更新失败和历史保留的区别

新批次未通过验收，不等于旧版本已被内容方撤回；上一套输入仍可读取或仍处于技术上的激活状态，也不构成撤回版本继续有效的依据。历史结果的保留与展示用于追溯，不绕过对当前建议有效性的限制。

## 精确的传递影响范围

用户在第 12 问选择限定到受影响的精确版本及其依赖：暂停直接或间接依赖被撤回版本的新推演，其他已确认有效且无该依赖的输入组合继续使用。下游内容受依赖影响而暂停使用，不等于 WP4 代替其内容负责方宣布它也被撤回。

影响分析区分运行依赖与版本替换沿革；版本较新或替换了旧版本，并不自动构成对旧版本的运行依赖。内容负责方若明确声明更广的撤回范围，应按该声明分析实际影响。

## 实现与治理范围

本 ADR 记录本仓库接受的生命周期原则。当前交界契约与运行时尚未明确实现版本撤回通知和消费响应；通知的可信来源、版本标识、依赖影响的验证方式及恢复条件需结合内容负责方和消费方继续落实，涉及交界约定时按 ADR 0004 执行。
