# In-memory deterministic core as the V1 acceptance path

Comparing the Pontegra quotation (PON-2026-EDMF-001, 2026-11-06) with our own design showed Pontegra's technical approach was strictly more aligned with the Pathfinder RFQ: in-memory roadmap graph as baseline, decision path as pure functions (no AI service, no network call, no wall-clock dependency), stable-ID ordering and canonical serialisation, pinned fixture seeds with reload-equivalence demonstrations, ok/blocked/degraded as a first-class status model, staging checksum with atomic snapshot activation, and a concrete k6 load profile for the p95 target. Our design doc 13 instead made PostgreSQL 16 + Apache AGE the primary graph engine — a claim the code had already abandoned (`pathfinder/core/graph.py` runs `InMemoryRoadmapGraph`; PostgreSQL serves only session/audit persistence behind repository interfaces), and which the RFQ §3.1 only allows as a separately identified option. Decided: the in-memory pure decision core is the V1 acceptance path; AGE/PostgreSQL persistence becomes an optional profile (O1-equivalent) off the critical path; the Determinism Contract, Result Status Model, import/activation protocol, version binding (incl. taxonomy and generator), /health runtime-mode reporting, CycloneDX SBOM, and the k6 load profile from the Pontegra design are absorbed into docs 12/13/14. Our differentiators over Pontegra are kept: parent-child rule trees, effective dates, rule conflict scanning, roadmap API views, and the WP-specific import aliases.
