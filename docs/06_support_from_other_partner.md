To successfully build the EPIDATA Pathfinder platform, you will need substantial support from multiple consortium partners.

The proposal is designed so that WP4 (your platform) is not standalone software development — it is a coordination/intelligence layer built on top of:

* EHDS infrastructure work,
* regulatory work,
* AI Factory work,
* use-case pilots,
* stakeholder engagement,
* and roadmap analysis.

So your success depends on receiving:

* structured inputs,
* domain knowledge,
* pilot access,
* validation feedback,
* legal guidance,
* and operational test environments.

Below is the realistic support matrix you should request.

# 9. Biggest Risk You Must Manage

The proposal is:

* policy-heavy,
* architecture-heavy,
* concept-heavy.

But many consortium partners may not fully understand:

* software product development,
* platform engineering,
* operational SaaS delivery.

So the biggest risk is:

> “Everybody provides abstract requirements, but nobody provides implementable specifications.”

You should therefore push aggressively for:

* structured schemas,
* tables,
* workflows,
* APIs,
* taxonomies,
* examples,
* operational scenarios,
* concrete evaluation rules.
