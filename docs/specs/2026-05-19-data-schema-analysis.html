Data Schema Analysis:
Mock vs. Real Consortium Data

Three Work Package datasets feed the Pathfinder compliance engine. What happens when the consortium delivers real data and the schemas don't match the mocks? This analysis maps every failure point and the fix radius.

01

WP2 — Stakeholder Taxonomy

stakeholder_type: string 唯一标识 (pharma-sme-001)
description: string 人类可读
capabilities: list[enum] 已有能力 (8 values)
pain_points: list[enum] 合规痛点 (6 values)

真实 WP2 (CHARITE) 约定的结构是 id + label + personas + user_journeys——stakeholder_type 字段名会变。

02

WP3 — Roadmap DAG

node_id: string 唯一标识
label: string 节点名
dimension: enum governance/data/compliance/infra/security
maturity_level: int 1-10 图的 X 轴
stakeholder_types: list[string] 适用方
prerequisites: list[node_id] 前置依赖

edge_id: string
from_node_id → to_node_id string → string
relation_type: prerequisite

真实 WP3 (Epidata) 可能用 id 替代 node_id，level 替代 maturity_level。

03

WP8 — Rules Engine

rule_id: string 唯一标识
rule_type: enum eligibility/exclusion/preference/override
priority: int 0-100
applies_to: list[string] → 匹配 WP2.stakeholder_type
condition: {field, operator, value} 或嵌套 {and/or: [...]}
action: {title, text, node_id, warning}
action.node_id: string → 指向 WP3.node.node_id
compliance_refs: list[string]
04

Data Relationships

WP2.stakeholder_type ──matches──→ WP8.rule.applies_to

                                       │
                                  WP8.rule.action.node_id ──points to──→ WP3.node.node_id

WP2 = "who is asking" · WP8 = "what to check" · WP3 = "where to go"

Fix Radius

One file: pathfinder/adapters/upstream.py. Plus ComplianceEvaluator for new operators.

def _normalize_node(raw: dict) -> dict:
    return {
        "node_id":   raw.get("node_id") or raw.get("id"),
        "label":     raw.get("label") or raw.get("title"),
        "dimension": raw.get("dimension", "governance"),
    }

Safety net: import_wp* methods validate after normalization and raise explicit ValueError.
