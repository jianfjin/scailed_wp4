Mock Upstream REST
Services

3个Mock REST容器(wp2/wp3/wp8), 用aiohttp统一服务端与客户端。Pathfinder在启动时通过aiohttp.ClientSession拉取mock数据, 替代现有demo_data.py文件加载。生产环境切换只需改环境变量。

01

Overview

REQUEST Chain
Client → Traefik → Frontend (page)
Client → Traefik → Backend (API)
Backend → WP2/WP3/WP8 Mock (fetch)
DATA Chain (response)
Mock → Backend (upstream data)
Backend → Client (JSON assessment)
Frontend → Client (SPA static files)

关键区分: HTTP请求发起者 = Backend (aiohttp GET), 但数据流向 = Mock → Backend (上游→下游)。 架构图必须分开画 REQUEST 和 DATA 两条线。完整闭环: Client 请求 → Backend 拉取上游 → 数据处理 → 返回 Client。

→ 完整辩论记录 (中文)

DecisionVote / StatusRationale
Mock REST 替代 JSON 文件 陛下否决 6:1 议会6人倾向于JSON文件方案(零新容器), 陛下坚持Mock REST方向以完整模拟生产拓扑
aiohttp 统一两端 Accepted 一个库覆盖server+client; async原生匹配FastAPI栈; httpx不加额外价值, requests同步阻塞淘汰
3容器 vs 1聚合Mock Accepted 独立容器 = 独立生命周期, 独立health check, 独立端口。生产切换时逐WP解耦, 风险最小化
UpstreamClient 缓存策略 Accepted 启动时fetch一次, 内存缓存。合规评估需要确定性 —— 同一session内数据不变
生产切换方式 Accepted 环境变量WP*_API_URL。UpstreamClient代码零改动
