System Architecture

Three-layer monolith. Single Docker container. Deployed via docker compose up -d.

Architecture Decision: Monolith, not microservices. 9/9 council seats agree. User base is < 500 invited stakeholders. Docker Compose single container. No K8s, no service mesh, no event bus.
Module Structure (project root):
api/ (FastAPI routes) · core/ (assessment, solver engines) · adapters/ (WP2/3/5/6/7/8) · models/ (Pydantic + SQLAlchemy) · rules/ (*.yaml) · migrations/ (Alembic) · config/ (env-specific settings) · exceptions/ (custom error hierarchy) · services/ (business logic layer) · scripts/ (CLI admin tools) · tests/ + tests/fixtures/

Data Schema

Four core tables. Minimal. Extensible through JSONB.

1. Roadmap Nodes (from WP3)

Show DDL 
CREATE TABLE roadmap_nodes (
    id              SERIAL PRIMARY KEY,
    node_id         TEXT UNIQUE NOT NULL,       -- 'R2.3-A'
    label           TEXT NOT NULL,              -- 'Establish DPO'
    description     TEXT,
    parent_node     TEXT,                       -- self-ref for DAG
    prerequisites   TEXT[],                     -- ['R1.2', 'R2.1']
    maturity_level  INT CHECK (maturity_level BETWEEN 1 AND 5),
    effort_estimate TEXT,                       -- 'low'|'medium'|'high'
    related_wp      TEXT,                       -- 'WP5'|'WP6'|'WP7'
    x FLOAT, y FLOAT,                          -- visualization coords
    metadata        JSONB,
    schema_version  TEXT NOT NULL               -- 'v1.0-m3-freeze'
);

2. Recommendation Rules (core IP)

Show DDL 
CREATE TABLE recommendation_rules (
    id                SERIAL PRIMARY KEY,
    rule_id           TEXT UNIQUE NOT NULL,     -- 'R-PHARMA-AI-001'
    parent_rule_id    UUID REFERENCES recommendation_rules(id), -- tree hierarchy
    rule_type         TEXT NOT NULL DEFAULT 'preference'
                      CHECK (rule_type IN ('eligibility','exclusion','preference','override')),
    node_id           TEXT REFERENCES roadmap_nodes(node_id),
    stakeholder_type  TEXT,
    condition         JSONB NOT NULL,           -- {"answers":{"q2.1":{"gte":3}}}
    action_title      TEXT NOT NULL,
    action_text       TEXT NOT NULL,
    compliance_ref    TEXT[],                   -- ['GDPR-Art.37','EHDS-Art.50']
    priority          INT DEFAULT 0,
    source_wp         TEXT,
    source_doc_ref    TEXT,
    created_at        TIMESTAMPTZ DEFAULT now(),
    updated_at        TIMESTAMPTZ DEFAULT now(),
    rule_version      TEXT NOT NULL
);
CREATE INDEX idx_rules_stakeholder ON recommendation_rules(stakeholder_type);
CREATE INDEX idx_rules_node ON recommendation_rules(node_id);
CREATE INDEX idx_rules_condition ON recommendation_rules USING GIN (condition);

API Design

Resource-centric REST. All business logic on server. Frontend renders only.

MethodPathPurpose
GET/healthLiveness + readiness probe (Docker healthcheck)
POST/v1/assessmentsStart a new self-assessment session
GET/v1/assessments/{id}Get current state and progress
PATCH/v1/assessments/{id}/answersSubmit answers for one step
GET/v1/assessments/{id}/reportGenerate Pathfinder report with recommendations
GET/v1/questionnaires/{type}Retrieve questionnaire definition by stakeholder type
GET/v1/roadmap/positionsRead-only proxy from WP3
GET/v1/compliance/checksRead-only proxy from WP8
POST/admin/rules/reloadHot-reload YAML rules without restart (admin only)
Rate Limiting: API gateway enforces 100 req/min per IP on public endpoints. /admin/* routes restricted to CHARITE internal network (192.168.0.0/16). Questionnaire responses rate-limited to 30 req/min per session to prevent abuse.

Architecture Risks & Tradeoffs

CRITICAL WP3 roadmap format is single point of failure

If CHARITE delivers a PDF instead of structured JSON, the graph engine cannot function. Mitigation: demand JSON/CSV node-edge list with topological proof by M2. No schema = no code. WP3 Plan B: data extraction layer — if structured data is delayed, implement a lightweight extraction pipeline that parses WP3 deliverables into the canonical node-edge format with manual QA sign-off.

HIGH WP8 legal constraints may not be formalizable

Lawyers write "should" and "may" — SAT solvers need boolean predicates. Architecture handles this with soft checks: flag risks rather than hard-block. Rules hot-loadable when WP8 updates.

MEDIUM CHARITE must maintain code in T4.3

Write "boring code" — no clever abstractions, no custom DSL, no deep inheritance. README explains deployment, not design philosophy. They need to add a rule, not understand the engine.

LOW Performance at scale

< 500 users, < 10⁴ roadmap nodes. Constrained graph search on DAG is sub-millisecond. Premature optimization is Mathematics Inc.'s enemy.
