05

Risk Register

CRITICAL WP3 delivers PDF roadmap instead of structured JSON

Mitigation: Demand JSON/CSV schema sign-off by M2. Include topological sort proof. No sign-off = refuse to start.

Plan B (Activated if WP3 delivers PDF): Deploy a data extraction layer: PDF→text parser → LLM-assisted structured extraction → human validation checkpoint → JSON. Graceful degradation mode: reduced path confidence scoring, manual edge verification required. Adds ~3 weeks to Phase 1 timeline.

CRITICAL Ambiguous requirements cause endless rework

Mitigation: M1 low-fi prototype with 3 options, signed scope boundary. Rework due to scope change = billable.

HIGH WP8 legal framework changes mid-project

Mitigation: Hot-loadable YAML rule engine. Never hard-code compliance. Update rules without redeploy.

HIGH Upstream WP2/3/8 data delayed past M12

Mitigation: Build with mock data from M1. Swap real data when it arrives. Decouple data from logic via adapter layer.

MEDIUM D4.1 acceptance criteria subjective

Mitigation: Quantified acceptance criteria in contract. 5 stakeholder types supported, ≥3 paths each, 100% WP8 rule match, ≤3s response.

Contract & Commercial Notes

COMMERCIAL Rework & Scope Change Rates

Three-tier rework rates. Cap: single scope change ≤15% of contract value, annual cumulative ≤30%. Tier 1 (minor): Within original scope boundary, no charge. Tier 2 (medium): Scope extension within WP4 remit, pre-agreed hourly. Tier 3 (major): New deliverable outside WP4, separate SOW required.

📄 Intellectual Property: Background IP and Foreground IP split per IP_BOUNDARY.md. DataWego retains ownership of generic engine components (graph traversal, constraint solver, questionnaire engine). Epidata/CHARITE own project-specific schemas, rules, and generated reports. Joint ownership of integration code with non-exclusive royalty-free license to both parties.
